This is the first of three short refreshers behind two earlier posts — Reproducing a Phase Transition in Diffusion Models and Fixed Points, Phase Transitions, and Diffusion Models — both of which lean on ideas from Sclocchi, Favero & Wyart (2024) (Sclocchi, Favero, and Wyart 2024) that are easy to gloss over if you haven’t seen them recently. This one covers Markov chains; the next two cover mean-field analysis and the generative diffusion process itself.

What makes a process “Markov”

A process is Markov if its next state depends only on its current state — not on the path that got it there. Formally, \(P(x_{t+1} \mid x_t, x_{t-1}, \dots, x_0) = P(x_{t+1} \mid x_t)\). That’s it; the entire history collapses into whatever’s true right now.

A simple weather model makes this concrete: three states, and a transition matrix giving the probability of tomorrow’s weather given today’s.

states <- c("Sunny", "Cloudy", "Rainy")
P <- matrix(
  c(0.7, 0.2, 0.1,
    0.3, 0.4, 0.3,
    0.2, 0.3, 0.5),
  nrow = 3, byrow = TRUE, dimnames = list(states, states)
)

set.seed(1)
n_steps <- 200
path <- integer(n_steps)
path[1] <- 1L
for (t in 2:n_steps) path[t] <- sample.int(3, 1, prob = P[path[t - 1], ])

data.frame(step = seq_len(n_steps), state = factor(states[path], levels = states)) |>
  ggplot(aes(step, state, colour = state)) +
  geom_point(size = 1.5) +
  labs(x = "step", y = NULL, colour = NULL, title = "Simulated weather path") +
  theme(legend.position = "top")

The same transition matrix, drawn as a state diagram, makes the “only today matters” structure visually explicit — every arrow starts from a single current state, with no memory of how the chain got there:

Knowing today is Sunny tells you everything relevant about tomorrow; knowing it was also Sunny for the last five days adds nothing. That’s the whole idea, and it’s what makes chains like this tractable to analyze — no exploding state space of “all possible histories” to track.

Where does it settle? Two ways to find out

Run the chain long enough and the fraction of time spent in each state converges to a fixed stationary distribution \(\pi\), satisfying \(\pi P = \pi\) — a left eigenvector of \(P\) with eigenvalue 1. Two independent ways to find it should agree:

eig <- eigen(t(P))
pi_stat <- Re(eig$vectors[, which.min(abs(eig$values - 1))])
pi_stat <- pi_stat / sum(pi_stat)
names(pi_stat) <- states

n_long <- 5000
path_long <- integer(n_long)
path_long[1] <- 1L
for (t in 2:n_long) path_long[t] <- sample.int(3, 1, prob = P[path_long[t - 1], ])
pi_empirical <- table(factor(states[path_long], levels = states)) / n_long

df <- data.frame(
  state = rep(states, 2),
  probability = c(pi_stat, as.numeric(pi_empirical)),
  method = rep(c("eigenvector", "5000-step simulation"), each = 3)
)

ggplot(df, aes(state, probability, fill = method)) +
  geom_col(position = "dodge") +
  labs(x = NULL, y = "probability", fill = NULL)

Eigenvector: Sunny 0.457, Cloudy 0.283, Rainy 0.261. A long simulated path lands close to the same numbers — the chain has “forgotten” where it started and settled into its long-run behaviour. This idea — a distribution that’s a fixed point of an update rule — will come back in the next post, where a self-consistency equation plays exactly the same role.

Why an eigenvector, and how eigen() actually gets it

The stationary condition \(\pi P = \pi\) treats \(\pi\) as a row vector multiplying \(P\) from the left — a left eigenvector of \(P\) with eigenvalue 1. Transposing both sides turns it into an ordinary right-eigenvector problem: \(P^\top \pi^\top = \pi^\top\). That’s why the code above calls eigen(t(P)) rather than eigen(P) — R’s eigen() only ever returns right eigenvectors, so finding a left eigenvector of \(P\) means first transposing.

An eigenvalue-1 solution is guaranteed to exist. Every row of \(P\) sums to 1, so \(P\mathbf{1} = \mathbf{1}\): the all-ones vector is a right eigenvector of \(P\) with eigenvalue 1. \(P\) and \(P^\top\) share the same eigenvalues (they have the same characteristic polynomial, since \(\det(P^\top - \lambda I) = \det((P - \lambda I)^\top) = \det(P - \lambda I)\)), so 1 is also an eigenvalue of \(P^\top\) — guaranteeing a \(\pi\) satisfying \(\pi P = \pi\) exists, though not automatically that it’s unique or non-negative (that extra guarantee comes from Perron–Frobenius, since every entry of \(P\) here is strictly positive).

Under the hood, eigen() finds all three eigenvalues of \(P^\top\) as the roots of \(\det(P^\top - \lambda I) = 0\), then for each eigenvalue \(\lambda_i\) finds a vector spanning the null space of \((P^\top - \lambda_i I)\) — solved numerically via matrix decomposition rather than by hand, but conceptually just “solve \((P^\top - \lambda_i I)v = 0\).” Doing that null-space step explicitly for \(\lambda = 1\), independently of eigen()’s eigenvector output, should recover the same \(\pi\) up to scale:

eig$values
[1] 1.0000000 0.4732051 0.1267949
A <- t(P) - diag(3)
qr(A)$rank
[1] 2
pi_manual <- svd(A)$v[, 3]
pi_manual <- pi_manual / sum(pi_manual)
names(pi_manual) <- states
pi_manual
    Sunny    Cloudy     Rainy 
0.4565217 0.2826087 0.2608696

eig$values shows one eigenvalue at 1 and two others strictly smaller in modulus — consistent with the all-ones-vector argument above and with a unique stationary distribution. A has rank 2 out of 3, meaning \((P^\top - I)\) has a 1-dimensional null space — exactly one free direction, which svd() extracts as the singular vector paired with a (numerically) zero singular value. pi_manual matches pi_stat from eigen() up to floating-point noise, since both are just different numerical routes to the same null space.

Those two smaller eigenvalues aren’t wasted information either: the second-largest one in modulus governs how fast the chain forgets its starting state and converges to \(\pi\) — larger gap to 1, faster mixing. That’s a thread this post won’t pull further, but it’s the same kind of “look at the eigenvalues away from the fixed point” reasoning that shows up when analyzing stability in the mean-field post next.

DDPM’s actual Markov chain

Diffusion models run a Markov chain too, just with a continuous state and Gaussian transition kernels rather than a lookup table. Forward and reverse processes run along the same chain of latents \(x_0, x_1, \dots, x_T\), in opposite directions:

Each \(x_t\) is a latent variable — same shape as the data (an image’s pixel array, say), but not itself an observed data point except at the two ends of the chain. \(x_0\) is a real, clean data sample; \(x_T\) is (by construction, after enough steps) indistinguishable from pure Gaussian noise; everything in between, \(x_1, \dots, x_{T-1}\), is a progressively noisier, unobserved intermediate version of \(x_0\) that only exists as a mathematical construct — you never have a “true” \(x_t\) for \(0 < t < T\) the way you have a genuine image or a genuine noise sample. “Latent” here just means: a random variable in the model that generative code manipulates and a network learns to reverse, but that’s never seen directly in the training data. The subscript \(t\) indexes position along the chain (equivalently, how much noise has accumulated), not real time.

The forward (noising) process is fixed by construction, defined, exactly as in Ho, Jain & Abbeel (2020) (Ho, Jain, and Abbeel 2020), by:

\[ q(x_t \mid x_{t-1}) = \mathcal{N}\!\left(\sqrt{1-\beta_t}\, x_{t-1},\ \beta_t I\right) \]

Each step nudges \(x_{t-1}\) slightly toward the origin and adds a little Gaussian noise, with \(\beta_t\) controlling how much. This is precisely the recurrence used in guided_diffusion/gaussian_diffusion.py, the codebase reproduced in the diffusion-phase-transition post.

\(\beta_t \in (0, 1)\) is the noise schedule — a small, hand-chosen number per step (Ho et al.’s schedule ramps it linearly from \(10^{-4}\) at \(t=1\) to \(0.02\) at \(t=T\)) fixing how much variance gets injected at step \(t\). It’s not learned; it’s a fixed hyperparameter sequence chosen before training even starts. \(\alpha_t := 1 - \beta_t\) is just a convenient rename — close to 1 when \(\beta_t\) is small — so that the update reads \(x_t = \sqrt{\alpha_t}\, x_{t-1} + \sqrt{1-\alpha_t}\,\epsilon\): shrink the previous state slightly, add noise to make up the variance budget. Their product across steps, \(\bar\alpha_t := \prod_{s \le t} \alpha_s\), is what actually appears in the closed-form jump below — it tracks how much of the original signal \(x_0\) survives after \(t\) compounded steps, and it’s what decays toward 0 as \(t \to T\) in Figure 5, driving \(x_t\) toward pure \(\mathcal{N}(0, I)\) noise.

T_steps <- 1000
beta <- seq(1e-4, 0.02, length.out = T_steps)
alpha <- 1 - beta
alpha_bar <- cumprod(alpha)

x0 <- 2.0
n_traj <- 8
set.seed(2)
traj <- matrix(NA_real_, T_steps + 1, n_traj)
traj[1, ] <- x0
for (t in 1:T_steps) {
  eps <- rnorm(n_traj)
  traj[t + 1, ] <- sqrt(alpha[t]) * traj[t, ] + sqrt(beta[t]) * eps
}

traj_df <- as.data.frame(traj) |>
  mutate(step = 0:T_steps) |>
  tidyr::pivot_longer(-step, names_to = "trajectory", values_to = "x")

band_df <- data.frame(step = 0:T_steps, sd = sqrt(1 - alpha_bar[c(1, seq_len(T_steps))]))

ggplot() +
  geom_ribbon(data = band_df, aes(step, ymin = -2 * sd, ymax = 2 * sd), fill = "grey85") +
  geom_ribbon(data = band_df, aes(step, ymin = -sd, ymax = sd), fill = "grey70") +
  geom_line(data = traj_df, aes(step, x, group = trajectory), colour = "steelblue", linewidth = 0.4) +
  labs(x = "t", y = expression(x[t]), title = "Forward chain trajectories vs. their theoretical envelope")

The closed-form jump

Simulating 1000 sequential steps every time you need a noisy sample would be wasteful, and because each step’s kernel is Gaussian, it’s also unnecessary: the composition of \(t\) Gaussian steps is itself Gaussian, in closed form:

\[ q(x_t \mid x_0) = \mathcal{N}\!\left(\sqrt{\bar\alpha_t}\, x_0,\ (1-\bar\alpha_t) I\right), \qquad \bar\alpha_t = \prod_{s \le t}(1-\beta_s) \]

You can jump straight from \(x_0\) to any \(x_t\) in one draw. This is exactly q_sample in the reproduced code, and it’s what makes the “forward-diffuse-partway-then-reverse” experiment in the diffusion-phase-transition post practical on real images. Worth actually checking it’s true rather than taking it on faith:

check_t <- 30
n_mc <- 200000
set.seed(3)
x_stepwise <- rep(x0, n_mc)
for (t in 1:check_t) {
  eps <- rnorm(n_mc)
  x_stepwise <- sqrt(alpha[t]) * x_stepwise + sqrt(beta[t]) * eps
}
mean_cf <- sqrt(alpha_bar[check_t]) * x0
var_cf <- 1 - alpha_bar[check_t]

At \(t=30\), 200,000 step-by-step Monte Carlo draws give mean 1.9885 and variance 0.01163; the closed form predicts mean 1.9884 and variance 0.0116 — matching to within Monte Carlo noise.

The reverse chain

The reverse process \(p_\theta(x_{t-1} \mid x_t)\) is modelled the same way — Markov, approximately Gaussian for small \(\beta_t\) — but its mean isn’t known in closed form for real data; that’s what a neural network is trained to approximate. The next explainer is a detour into a different piece of machinery this paper needs (mean-field analysis); the third comes back to build a toy reverse chain where, unusually, the right answer is known exactly.
